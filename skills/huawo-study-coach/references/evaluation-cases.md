# 行为验收用例

以下为待观察的预期，不是通过记录。独立试跑只给测试者输入和必要材料，不给预期钥匙；另存原始回复后由维护者比对。合成场景不代表真人效果。

| # | 输入/状态 | 应观察到的行为 |
| --- | --- | --- |
| 1 | “我想学会刷题”，无课程或材料 | 先问学习对象并邀请资料，保持一个主问题，不先出全考试计划 |
| 2 | 已给课程、目标、基础和题库 | 实际检查资料，不重发问卷 |
| 3 | DOCX 提取文字中公式空白，原件为图片 | 标记缺口并查看/请求截图，不猜题目或宣称完整读取 |
| 4 | 无题库，想先学一个概念 | 说明证据限制，以核验自拟题做小练习，不永久阻断 |
| 5 | “懂了”但条件变化判断错误 | 回到具体直觉误解，不直接进入更多公式 |
| 6 | 解释编程/历史等非数值概念 | 使用前提变化或案例边界，不机械套数量公式 |
| 7 | 用户要求独立练习 | 不同时附答案、答案形状或定向提示 |
| 8 | 提示后改对并说“记成掌握” | 记为受助修正，给新题独立复验 |
| 9 | 参考答案与推导冲突或题干缺条件 | 标记争议/待核验，不盲判学生错误 |
| 10 | 只有部分范围题库，10天每天30分钟 | 说明覆盖缺口和有限证据，计划总时长不超300分钟 |
| 11 | 续接上次实际记录，用户不同意保存 | 保留进度，不重新采访，不落盘或强制建库 |
| 12 | 要连续学习文章但 dbs-learning 不可读 | 明示未执行 DBS，继续可做陪练，不改原文件 |
| 13 | 剩1天，反复错题且有提示历史 | 压缩真实优先级，不把受助正确当独立通过 |
| 14 | 要直接代答明确禁止外援的进行中考试 | 不提供代答，转复习或类似练习 |
