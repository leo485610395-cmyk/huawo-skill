# 分流交接

本工具识别和建议，不调用主路由或其他Skill。这里的“交回”是在同一对话中交付可继续处理的信息，不是创建代理、调用虚构API或要求用户另开聊天。

## 带回什么

只保留本任务需要且已知的信息，空缺明确留空，不让用户重新填写：

- 原问题与本轮希望得到的结果，能引用时保留关键原话。
- 当前用途、材料、已有尝试与反馈，哪些部分已经解决或确认。
- 本轮A／B判断或尚不能判断，最简依据，以及剩余的一条信息/证据缺口。
- 一个下一步与需要观察的结果；若仅需解释或资料查询，不强加实作。
- 建议承接方式、工具条件与已有操作/分享边界。

输出只需几个短项，来源与依据不包含未公开的内部推理。没有进行过外部检索、制作或工具调用时，不声称已经完成这些动作。

## 调用者怎样接续

1. 若分类尚不明确，等待本工具提出的那个关键问题的真实回答，不再叠一轮同义采访。
2. A由调用者直接解释、推理或查询。资料不全就处理具体缺口，不转成“做一次才知道”。
3. B由调用者从已有进度执行或带用户完成一小步，不再把本工具刚给的建议当新问题送回来。
4. 先A后B先补一条关键条件；补完后沿用当前目标与材料继续，不重问已确定的用途。
5. 建议goal、fear、study或实作工具时，调用者先确认实际可用并完整读取其指令，保留叶子的适用范围与确认要求。本工具只给建议，不报告调用成功。
6. 新工具缺失时，调用者说明未执行该工具，在现有能力内处理；不可缺的条件才请求补齐，不自动安装。

同一卡点只识别一次。只有用户的新事实、纠正或本轮目的改变时才重新判断；不得形成“主路由→本工具→主路由→再次本工具”的循环。

## 独立调用

没有主路由也可使用：提供分类、简短依据与一个下一步后停止，不要求用户安装其他工具。不自动带做、不替本人确认成果，也不把“试一试”的建议写成已经实践。

如果需要真实判断而本人尚未回答，就保留该缺口。用户不想实践、只想看说明或决定结束时，按这个范围交付，不继续催促。
