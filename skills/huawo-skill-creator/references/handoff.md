# 从留经验阶段接手

## 带来什么，沿用什么

只整理实际已知的内容，不要求每个字段先填满：

- 原任务、给谁用、用户想改变什么；
- 用户提供的材料与实际可读范围、成果位置和有效版本；
- 谁已确认什么，哪些只是生成或技术检查完成；
- 实际步骤、关键选择、失败尝试及修改理由；
- 前序沟通中用户已经表达的想法、坚持与顾虑，选过和放弃过什么、原因是什么，哪些说法被用户更正；关键处保留可核对的原话，不只留下最终步骤；
- 用户认为有效的做法与AI新增建议，分别记；
- 下一次可能遇到的同类任务、当前缺口；
- 当前用户原话所覆盖的创建、保存、安装和公开范围。

交接不等于重新做身份采访。收到文件路径时先核对材料是否获准、是否真实可读；不要扫描整台电脑寻找更多案例。不能从本次使用的工具反推原成果的制作者。

## 先保留，再判断问题与缺口

从当前宿主能够读取的对话与获准记录恢复，不要求换工具或重开对话。保留对话中实际表达的想法与理由，不索取或虚构模型未公开的内部推理。将记录分为：

- 这次的事情、成果及确认状态；
- 用户的想法、原有判断、关键原话、取舍原因和更正；
- 宿主AI实际协助了什么、提出过什么建议、哪些被采用或仍待试；
- 下次可能怎样复用，用户已提出的未来要求与尚缺的一点；
- 已授权的材料、保存和操作范围。

这份记录是继续工作的底稿，不是要求用户再填一份表。已有明确保存位置及文件写入授权时，在该工作区实际保存一份私有经验交接记录并回读，放在生成Skill目录之外；不覆盖已有文件，不把完整聊天或私人原件默认复制进去。不另建知识库作为前提。只能保留在当前对话时如实说明，不能宣称已持久保存。

引用关键原话时保留原意及其来源角色；更正后的判断作为当前版本，原选择及修改理由仍可追溯。只保留能支持这次复用的内容，不自动扫描宿主历史或复制无关隐私。没有权限或看不到的前文标未取得，需要时只请求最关键的片段。

建议、用户要求与已实际执行的动作分别记；只有材料或可见操作支持的贡献才能归给人或宿主AI，不能从成品存在推断谁起草、检查或确认。未知的作者和动作保留待核，不用概括补成历史事实。

承接之后先从上下文判断反复问题、可复用规则、适用变化、结果与验收是否足够清楚，再按最影响设计的缺口采访。未来委托范围只是其中一项；不能固定先问AI做到哪一步，也不能因上游总结过经验就默认问题与规则已确定。已经说清的直接沿用。

## 适合做候选的信号

| 检查什么 | 从已有上下文寻找的依据 |
|---|---|
| 反复问题 | 下一次同类情境、反复卡点或需要稳定完成的判断/操作；任务频繁本身不足以说明问题 |
| 可复用做法 | 哪些步骤、判断依据和纠错方法跨案例仍有用，哪些只是本次特例或AI待试建议 |
| 可观察结果 | 用户想发生的变化、Skill交付及完成证据、由谁核对 |
| 输入与资源 | 必要材料、允许变化、现实可得的权限与工具 |
| 适用边界 | 哪些输入或条件使规则失效，何时另处理、追问或交人确认 |
| 复用收益 | 比笔记、模板、现成工具或普通对话减少哪些重复判断或操作，是否值得维护 |

这些是内部判断维度，不是六道强制问答。不要求已重复成功固定次数；一次案例能支持待试候选，不能证明广泛适用。问题或方法不清时只问影响下一步的缺口；核心结果不可观察或关键权限长期不可得时收窄任务，必要时保留笔记或模板。

## 几种接手状态

| 当前情况 | 下一步 |
|---|---|
| 用户已要求做Skill，交接足够 | 复述拟解决的问题和主要边界，生成候选 |
| 用户已要求做Skill，关键判断缺失 | 从一个真实决定追问，一次一个问题 |
| 只有上游建议，用户未表态 | 先问是否愿意把这部分经验做成可试用Skill |
| 用户只要笔记或不想继续 | 完成笔记或收尾，不创建候选 |
| 原成果仍待本人或专业确认 | 先处理原核对；若用户明确要提前做，只做待验证候选并保留人审 |
| 没有真实案例，但明确想试新流程 | 从一个最小任务或注明是假设的样例起步，规则标待试，不包装成成熟经验 |

Skill候选与业务成熟是不同状态。一个真实案例可以支持初版，不能证明所有变体都适用；不为了凑样本让用户等待，也不因为一次成功承诺稳定效果。
