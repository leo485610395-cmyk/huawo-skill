# 把用户的判断问出来

## 选择下一问

先按交接指引保留前序沟通中的做法、想法和取舍，再找哪个未知最会让下一步走岔。不要只记一个最终步骤表而丢掉用户为什么这样做。

由huawo-ai-doudi接来时，沿用其已有梳理，但核对制作判断是否足够：反复遇到什么问题、哪些做法能跨案例复用、输入会怎样变、何时需换做法或停下、交什么及怎样验收。不能默认原经验已经回答这些问题，也不固定先采访未来委托范围。

选择会最先改变设计的未知：连问题都不明确，先问真实的重复情境或卡点；问题清楚但规则含糊，问具体判断依据；规则已清楚但适用变化、验收或权限缺失，再问相应缺口。已有可靠答案跳过，能从获准文件查到的先查。一次只问一个主问题，回答后重新判断下一步；不是按顺序问完一份清单。

常见追问角度按需使用，不整套发给用户：

| 真实缺口 | 可以怎样问 |
|---|---|
| 只说任务经常发生，具体重复问题不清 | 最近一次反复卡住的具体事情是什么？ |
| 只有“每次都很麻烦” | 最近一次具体发生了什么？ |
| 只有步骤，没有判断 | 你当时根据什么决定先处理这一项？ |
| “看情况”“差不多” | 哪个具体信号会让你换一种做法？ |
| 只讲顺利案例 | 最近遇到过哪种情况，让原做法不适用了？ |
| 不清楚哪些能跨案例复用 | 换成下一次任务，哪一处会需要换做法？ |
| 有成品，完成标准含糊 | 这份结果中，你会先看哪一点决定能不能用？ |
| 输出需要他人确认 | 哪一步要交给谁判断，AI可以先做到哪里？ |
| 问题和做法已清楚，仅委托范围未定 | 下次遇到这类事，你希望这个Skill帮你做到哪一步？ |

每个问题只问当前最关键的一件事，不把表里的问法合成一个长问题。用户已有明确规则和材料时，核对实际材料后直接整理，不强迫重新讲一次。采访要取得具体决定、可见依据、例外和验收标准；只得到步骤或工具名称仍可能缺判断。

## 复述与修订

在足以影响执行的节点，用几句说明目前理解的用途、关键规则及仍待确认的一点，让用户纠正。不要每轮都输出完整业务报告。

记录规则的证据状态：

- 用户说明自己确实这样做：记为本人做法，保留适用情境。
- 可读取文件或实际操作支持：记来源与已读范围。
- AI提出的新分支或优化：标为建议/待试，不能冒充用户成熟方法。
- 用户两次说法冲突：保留冲突，问一个能决定取舍的问题。

必要时对照另一件获准案例，或用一个明确标注为假设的条件变化检查边界，例如材料不齐、结果冲突、对方没有确认。没有第二例就标未验证，不能编历史或把本次特例推广成共同规则。用户还没有方法时，可提出待试建议，不要求其先成为专家或代替AI核实外部事实。

## 可以开始写文件的条件

已经足以确定反复问题、触发情境、输入变化、输出与完成证据、可复用判断和停止条件，就能先生成候选。剩余未知不会改变主要结构时透明标为待试；会改变方向、验收、专业结论或授权的未知先补清。

不用把用户的所有经验全部挖完，也不用把这一次案例的每个细节写成通用规则。模板里保留位置、日期等变量；敏感材料的真实值不进入可分发Skill。
