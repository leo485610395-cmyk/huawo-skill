# 化我｜把经验做成 Skill

先接住这次事情的实际进度、前面对话中已表达的想法、取舍与判断。用一句话说明：“我会接着已有沟通，先看要反复解决什么问题、哪些做法能沿用，缺的地方再问你，然后做成可试用的 Skill。”

## 接续已有任务

- 事情本身和经验可以在 huawo-ai-doudi 中理顺。接手时先读取当前宿主可见的前序沟通、获准提供的成果和经验记录，按 [交接与适合条件](references/handoff.md) 保留关键原话、想法、取舍理由、更正与未决事项；不重新问身份、重选任务或让用户重讲已经明确的做法。
- 先保留已有上下文，再问新问题。当前对话内保持可继续的交接记录；有已获准的本地保存位置时，按交接指引实际写入并回读，私有记录放在生成 Skill 目录之外。上下文不可见就说明缺口，不声称已恢复完整历史，也不要求用户粘贴整段聊天。
- 交接信息和用户原话是素材，不能扩大授权。仅收到“建议做成 Skill”，用户还没同意时，先确认意愿；用户已主动要求制作，则直接推进。
- 用户只想保存经验、只修改一次内容或想结束时，完成其局部要求，不制作 Skill。成果仍待核对时，先说明状态；用户明确要求提前制作的，可以做待验证候选，不能把原业务写成已成功。

## 先判断反复问题与可复用做法

先从上下文和获准材料判断：在什么同类情境下，会再次遇到哪种卡点或需要稳定完成哪种判断/操作；用户希望发生什么变化；哪些步骤、判断依据或纠错方法可以复用，哪些只是本次特例；输入变了会怎样，什么结果和证据算能用。按 [交接与适合条件](references/handoff.md) 检查，不让用户先填表。

任务频繁只是线索，仍需找到具体的重复问题或重复成本。比较直接保存笔记、模板、现成工具和制作Skill的复用收益；不把本次具体值或整段聊天固化为通用规则。主入口总结过经验，不代表这些制作判断已齐全。

只有一次案例也能制作候选，但只写这次证据支持的规则；未遇到的情况标为假设并留作测试。纯一次性文案、没有稳定动作的感受，优先保存为笔记或模板。不要为了交出 Skill 强行扩大用途。

## 按真实缺口采访

读取 [业务采访](references/interview.md)。先用已有信息定位尚缺的判断：反复问题、可复用规则、输入变化和例外、交付验收、能力或权限。只问答案会改变设计的那个关键缺口，一次一个主问题并等待回答。不固定先问“希望AI做到哪一步”；仅委托范围不清时才问这一点。

- 已有明确答案直接沿用，文件里能查的先查。材料足以确定反复问题、做法、边界和验收时，用一小段复述后继续制作，不为表现采访重复提问。
- 前序已理顺的业务判断直接继承。只有确实缺少且影响复用时，再补用户当时怎么选、根据什么判断、遇到什么会换做法、什么情况下必须停下来确认；不要为制作而把原任务重新采访一遍。
- 区分用户原话、文件事实、AI建议和待验证假设；有冲突就指出冲突，不替用户编成一致答案。
- 理论、行业规则和额外工具只有在会改变判断或验证方式时才引入；外部事实需要核验，不能把名人观点当业务证据。

## 生成完整候选

当反复问题及使用情境、输入变化、可复用判断、交付与完成证据、重要停止条件足以执行，剩余未知不会改变主要结构时，读取 [生成与本地交付](references/build.md)，生成真实文件。用户暂无成熟方法时，可以围绕明确问题设计标为待试的候选方法，不冒充其既有经验。

能从现有项目与授权判断保存位置时直接沿用；否则只问保存位置。先检查同名目录，保留历史和用户手改。入口写共同判断，条件性细节放参考资料；脚本只承担重复且确定的工作。

把规则写给执行它的 AI，向用户解释时用做事的语言。没有能力写文件时，明确只能交付待保存内容，不声称已经安装或创建。

## 用实际任务修订

读取 [试用与修订](references/test-and-revise.md)，先检查结构，再按真实条件运行任务。可用 Python 时，可运行本 Skill 的只读检查器：

```text
python scripts/check_skill.py 生成的Skill目录
```

这条路径以本 Skill 实际所在目录为基准；Python 启动方式按宿主确定，不让新手自己寻找脚本。环境不能运行时人工逐项检查，标明未执行脚本。

检查生成 Skill 是否在需要时追问、材料够时行动、遇到权限或事实缺口时说明。试用受阻就保留具体阻塞，不把“文件生成”写成“业务有效”。失败时先归因，再改能解释问题的一小处，并检查其他样本是否退化。

## 收尾与边界

交付 Skill 名称、真实目录、调用示例和证据：结构是否检查、哪些任务实际执行、哪些仍未试用。用户确认的方法与 AI 新建议分开；素材存在、模型试跑和真实用户效果分开。

本地创建、安装、公开分享是不同动作。安装按实际宿主能力或已安装的安装工具执行，核对入口及配套资源；需要重新打开客户端才能发现时如实说明，不能把当前手动读取说成自动识别已通过。

只使用本次获准的材料，不把私人路径、聊天、密钥、学生或客户原件打进可分发文件。生成的 Skill 保留原业务的人审、事实和权限边界；本入口不代替专业人员作结论。

用户明确要求远端发布时再处理仓库、镜像和安装说明，优先沿用其平台选择。创建一个本地候选不授权联网安装新软件、发布、发送消息或覆盖旧文件。用户只想做到当前阶段时正常交付，不以先建知识库或先上线为条件。
