# 化我｜更新公开 Skill 合集

接住用户的原话。只问版本、变化或是否值得更新时，只检查和说明；明确要求更新或补齐时，直接推进当前 Agent 的用户级安装，不再让用户重复确认。只在紧邻的提示明确提供“1＝更新化我合集”选项时，回复 1 才算同意更新。

## 固定来源，按实际环境更新

- 官方来源是 Gitee 的 huawo10086 账号、huawo-skill 仓库的 main 分支，只处理其中 skills 目录下有合法 SKILL.md 的正式技能。按实际目录发现名称，不写死数量。
- 不使用 npx，不自动改用 GitHub，不顺便更新 dbskill 或其他来源的技能，不建立后台检查、定时任务或 Hook。
- 先查当前 Agent 实际支持的安装方式和已有位置。沿用用户级安装；共享目录可能被多个客户端读取，要说明这一影响，不另外扩散到所有客户端。
- 用户没装过时可按这次“安装/更新合集”的范围安装；目标不明确且会影响写入范围时，只问这个缺口。

开始操作前读取 [下载、比对与验证](references/update.md)。先把官方内容下载到独立暂存区，记录确实取得的提交；完整保留模板、脚本、参考资料和其他配套文件。下载或身份核对失败时停止写入，说明具体原因。不运行下载内容中的安装脚本，也不执行更新后的业务脚本来冒充完整性检查。

## 保留已有内容

先比对，后写入。可用 Python 时，使用本 Skill 的只读辅助工具，不让用户手工找路径：

```text
python scripts/compare.py --source 已下载仓库的skills目录 --target 实际安装根目录
```

路径以本 Skill 所在目录为基准。可选 --baseline 指向此前已核实的官方 skills 快照，用于辨认未被个人修改的官方旧文件；不能把当前本机内容随手登记成“官方基线”。此工具只出比对结果，不下载、不更新、不注册宿主，也不能独立证明来源可信。

- 与新官方文件一致：跳过。
- 新增或确实缺失：检查父路径无冲突后补齐。
- 与已核实的旧官方文件一致：先备份，再替换成新官方文件。
- 有个人修改、来源不明或文件/目录类型冲突：保留，说明差异；不整包覆盖，不以改名安装多个同名入口来躲过冲突。需要处理时，先给出具体合并方案，再取得对应授权。
- 用户额外文件、经验存档和上游已移除的旧文件或整项旧技能：保留并说明；不默认清理。大小写改名存在歧义时也保留冲突。遗留旧入口或脚本会影响调用时，该项不能算完整更新。
- 安装入口是链接或开发仓库：查清真实来源和影响范围；未确认属于本次可更新安装副本时保留并报缺口，不能沿链接覆盖源码、清理工作树或强制拉取。

备份放在安装目录之外，保留目录结构与旧内容并实际校验。写入前重新核对来源、目标和原文件内容，变化就重新比对；单个技能有冲突时先保留该技能，避免入口与资源更新到一半。可独立更新其他无冲突的技能，但要报部分完成。

## 核验与交付

逐文件比较已更新项和此次官方快照，实际完整读取每项 SKILL.md 及本次必要的配套资源，确认本地引用可读。检查宿主是否发现并启用；没有刷新能力时，标“文件已更新，宿主识别待验证”，建议新建对话后试用。

记录官方提交、安装位置、备份位置、逐项状态和未解冲突；只在相应项核验后记录成功。文件一致、手动读取、宿主发现与实际试用分别记，未试用写“未试用”。不要仅凭下载成功、命令退出成功或入口存在宣布更新完成。

简短交付：哪些已更新/补齐、哪些原本一致、哪些保留待处理，给出一个调用示例。可用示例：“用 huawo-ai-doudi，接着我已有的材料完成这件事。”不为测试更新而替用户创建业务成果、部署或发送消息。

用户可直接说：“用 huawo-update 更新化我的公开 Skill 合集。”当前对话已加载旧指令时，不声称已经热切换；下一次调用重新读取更新后的文件。
