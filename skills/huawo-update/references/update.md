# 下载、比对与验证

## 只检查还是更新

“有什么更新”“现在是什么版本”“要不要更新”只读；“更新合集”“安装/补齐最新的化我技能”才写。版本用实际取得的提交标识，技能没有版本号就不编造。本地未留来源记录时说“旧版本未知”，不能从日期猜版本。

## 取得可核对的官方快照

若 Git 可用，使用新的暂存目录，不把已有安装目录当下载目录。仓库地址由本入口给定身份构造，为 https://gitee.com/huawo10086/huawo-skill.git 。可使用以下方式，路径按本机正确引用：

```text
git -c core.autocrlf=false clone --branch main --single-branch https://gitee.com/huawo10086/huawo-skill.git 新暂存目录
git -C 新暂存目录 rev-parse HEAD
git -C 新暂存目录 remote get-url origin
git -C 新暂存目录 status --porcelain
```

核对真实来源、提交和未修改工作树。旧暂存区有用户修改时不重置它。Git 不可用时可使用当前工具支持的 Gitee 下载/API，记录实际能核对的版本；解压前检查成员路径，拒绝绝对路径、上级逃逸和外部链接。无法核对来源或安全取得完整内容时说明受限，不默认安装新软件或回退其他平台。

需要做历史比对时，沿用此前更新记录对应的官方快照，或从同一官方仓库取得具体历史提交的独立快照；检查它包含的内容，不能使用未经核对的第三方副本。没有可信旧快照不妨碍检查，只是同名差异默认冲突。

只有正文中给 Agent 的技术文档才需要完整地址。给社群成员的安装/更新话术写账号名、仓库名和调用名即可，不放可点击网址或安装命令。

## 目标与比对结果

当前 Agent 能读写文件时，确认它的用户级安装根目录；桌面产品只支持导入时，按实际导入/升级能力处理，不伪造本地目录。不能从下载目录存在推断产品已识别。

Python 3.10 及以上可运行只读工具，Windows 中文环境优先使用可用的 Python 加 -X utf8：

```text
python -X utf8 scripts/compare.py --source 官方快照/skills --target 用户级skills目录
python -X utf8 scripts/compare.py --source 新官方快照/skills --target 用户级skills目录 --baseline 已核实旧官方快照/skills
```

工具输出 JSON：各技能的 same、add、replace、conflicts、retained。replace 只表示本地旧内容匹配给定旧快照，仍须先核实基线身份。无 baseline 时只会建议新增、跳过或保留冲突。linked/blocked 表示该技能不能按普通目录更新。工具不会证明宿主支持目标路径。

大小写不同但可能指向同一文件/目录时，工具保守报冲突；来源中互相仅差大小写的路径会被拒绝，避免跨文件系统出现碰撞。retained_skills 列出可信旧快照有、新版已移除而本地仍在的整项技能，legacy_entries_pending 标明遗留入口待核；all_official_files_match 只说明新版应有文件一致，不能抵消这些待处理项。没有可信旧快照时，整项下架检测标为不可确认，不说已排除所有旧入口。

退出码 0 表示已成功完成比对，可能仍有冲突；2 表示输入、来源结构或读取失败。必须读结果，不能仅看退出码。没有 Python 就按同样规则用现有文件工具比对，不为本 Skill 安装 Python。

## 安全落盘

1. 将比对记录留在安装目录之外。每个将要修改的技能先检查所有冲突和路径；有任一冲突，该技能整项保留，先交付具体差异。
2. 备份将被改变的已有技能完整目录到独立新位置，不覆盖旧备份；本地私有资料只留本机，不打进分享包。先校验备份中的旧文件与原件一致，再开始写入。只新增技能无需伪造旧版备份。
3. 对无冲突项重新核对 source_sha256 与 before_sha256，确保从比对到写入期间内容没变；目标仍是原来核实的普通目录，父路径没有变成链接或文件。按文件添加/替换，完整保留额外文件，不递归清空或删目录再复制。已有单个文件替换宜使用同目录临时文件与原子替换；系统不支持时如实说明能力。
4. 写入失败就停止该项并记录已变更文件，不继续启动其业务；用已核实备份恢复本次覆盖的文件，不能为了恢复去清空目录或删除用户新增内容。恢复后也要回读。不具备可靠回退能力时，在写前说明并采用宿主原生升级机制或保留待处理。
5. 再运行比对并读取入口/必要资源；官方应有文件全部一致才算文件更新核验完成。retained 中包含上游旧文件时单列，若有额外入口/运行脚本影响新行为，标待处理，不说“与仓库完全一致”。

保留此次官方快照/取得方式、官方提交、目标路径与逐项结果，供下次作为可信历史线索。记录不能将保留的个人差异冒充官方文件，不能仅写一个成功时间掩盖部分失败。没有状态记录也能下次重新检查。

## 宿主识别和试用

每项回报到实际做到的层级：文件哈希一致、入口及资源读取、宿主识别、具体任务试用。只有真正运行过的任务才写“试用通过”，否则写“未试用”。如已安装与新官方完全一致，可以跳过写入，但仍说明宿主识别与试用是否有证据。

一项冲突不等于全部失败，其他项成功也不等于合集全部更新。报告简短列出成功项、保留项及具体阻塞；未获授权不跨 Agent、发布、发送消息或更新任意其他仓库。
