# 首次成果 → 最小知识库

只在用户确认保存、或主动要求搭知识库时读取本文件。知识库是把这次做成的事情接到下一次，不是做第一件事的前置考试。

## 1. 先确认要不要保存

首次成果达到约定验收后，只做一个可拒绝的邀请：

> 要不要把这次的资料、已确认成果和有效步骤，保存成一个小知识库，下次可以接着用？

用户已经明确要求保存或搭建时，沿用该授权，不再重复问。只要草稿、想结束或拒绝保存，就结束原任务；不把“不建知识库”判为没完成。成果尚待本人或专业人员确认时，不写成已验收；用户要提前保存，可以按真实状态存档。

首次邀请只针对本次任务，不等于许可长期读取电脑、记录全部聊天或对外共享。

## 2. 复用已经确认的信息

从当前对话提取四类内容：

1. 本次任务实际使用、允许保存的原始材料及出处；
2. 用户确认的成果版本、验收情况，以及仍待确认的部分；
3. 有效提问、步骤、修改理由和用户自己的判断；
4. 未解决的问题与下一步。

不重新做一套身份、目标或心理采访。只保存任务需要且用户已确认的事实；AI对人格、心理的推测不写入用户档案。未确认的信息标为待确认，不用猜测补齐。外部反馈按原话和来源记录，不自动升级为效果已证实。

缺保存位置时，只问目标文件夹。如果材料含学生、公司或他人信息，先确认哪些可保存、是否需要脱敏；检查密码、密钥、联系方式及未授权截图，不把完整聊天默认当资料。

## 3. 根据现有条件，建立或补充

### 已有知识库或已解压模板包

先完整读取它的实际入口与相关规则，查看索引、有效版本和现有目录。以现有结构为准，按本次授权补充，不新建并行系统、不覆盖历史。

化我的基础包采用 `AGENTS.md`、`INDEX.md`、`SOURCE_OF_TRUTH.md`、`_项目状态.md` 和 `system/` 等入口。只有实际能读取包和指南时，才按其流程执行；不能声称从名称就读过模板。已经确认的个人情况和协作偏好直接沿用；其余不影响本次保存的字段留待确认，不强制补完。

原始材料保留在资料区，成品另存输出区。同步登记文件位置、版本和状态，再写一条任务实践记录。已有文件含用户改动时，先核对，只补相关内容；新增版本，不静默替换当前有效版本。

### 没有知识库，也没有模板包

无需先下载安装包。获得目标目录和本次保存授权后，用宿主真实可用的文件工具，在指定目录建立轻量起点：

```text
INDEX.md                 入口：本次任务、文件位置和继续方式
SOURCE_OF_TRUTH.md       有效材料与成果版本、状态、确认人或来源
_项目状态.md             当前用途、已完成、待确认、下一步、暂不处理
01.资料库/               获准保存的原始材料；原件不改写
02.输出区/               成果副本或可定位的原文件；新版本另存
02.输出区/本次实践记录.md   有效提问、实际步骤、修改理由与坑
```

这是从本次成果生长出的最小知识库，不宣称已经完成基础包的全套搭建。用户以后需要身份、协作风格或更多项目管理时，再接基础包；不要为了填结构增加无关文件或问题。

创建前检查目标位置是否已有文件；有冲突就沿用规则或询问，不覆盖。原材料可以记录真实位置而不复制敏感文件。文件路径、版本和验收状态必须对应真实文件或实际可访问的内容；仅有链接时注明访问是否核验，不宣称文件已保存。

### 无法读写文件或无法访问材料

明示限制；提供最少可复制内容及应保存的位置，交给用户保存。未实际写入就只能说“待保存”，不得称知识库已搭好。需要下载、付费、扩大授权或使用外部同步时另行确认，不把它包含在保存授权里。

## 4. 回读检查，再收尾

实际写入后，重新读取入口、登记、状态和实践记录，并核对引用的成果位置及文件存在情况。只从这些文件回答：

- 这次做了什么、拿来干什么？
- 当前有效成果在哪里，是什么版本与确认状态？
- 下次能复用哪些步骤或提问？
- 下一步是什么，哪些事情暂不处理？

资料缺失就明确说不知道；发现记录与实际文件不符，先修正。原材料不得因归档而删除，已确认版本不得被新草稿悄悄取代。

交付具体入口位置和实际回读结果。下次让能读文件的 AI 打开这个目录，先读现有知识库的实际入口；本次新建的轻量起点先读 `INDEX.md`。文件可读取才有续接基础，不承诺跨对话永久自动记忆。如果只在本轮回读，不声称已经通过新对话冷启动测试。

群内分享和公开发布另行自愿确认，本地保存不等于公开。完成这一步后正常收尾，不自动升单或制造新任务。
