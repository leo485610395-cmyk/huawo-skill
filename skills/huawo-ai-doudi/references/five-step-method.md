# AI兜底五步法

## 方法目标

从一个具体的“第一次”出发，让用户理解基础知识、找到信息途径、做出第一版、接收反馈，并留下下次能用的经验。用真实尝试积累底气，不要求先成为专业人士，也不保证达到统一分数。

五个步骤保留原来的逻辑：**交付 → 材料 → 判断 → 流程 → 沉淀**。面向新手时，讲成：**定交付 → 备材料 → 做判断 → 跑流程 → 留经验**。

只讲用户当前需要的一步。已经有成果或反馈时，从那里继续。

## 1. 定交付：为什么做，这次先验证什么？

先恢复已有目标。任务尚未定义时，想清这件事要帮谁、解决什么，理想情况下对方或自己能做什么；再从结果反推哪些信息、证据、资源、行动、质量和安全条件必须成立。对理想结果保持乐观，对当前条件与判断保持求证。

只抓一个最影响本轮行动的未知，区分事实、假设与待核实之处；用一次小实践验证它。目标已经清楚时不重复追问“为什么”，只说出这次要做的事和怎样检查。

把“学AI”“变厉害”落到一个有用途的小成果。还不明确才问：“你最近有哪件想做、但还没开始的事？”

交付可以是一份可看的初稿、能本地打开的网站、一次交流准备或一份可核对的分析。不要替用户把目标升级成接单、创业、发表或商业上线。

明确：谁会用、用于什么场合、第一次怎样算完成、看到什么反馈才算朝理想结果前进。能用一个句子表达就够，不为了格式加提问。首次成果不是理想结果本身，也不能证明方法已经稳定有效。

例子：做一个个人介绍网页，让新认识的伙伴知道我是谁、正在做什么；本地打开、真实信息核对和一轮修改就构成第一项练习，不必马上买域名。

## 2. 备材料：我已有些什么，还缺什么？

区分三种材料：

- 用户能提供的真实信息或原始资料；
- 需要理解的基础概念与操作；
- 需要查证的事实、条件或专业资料。

让AI根据具体问题解释概念、指出查找线索、帮助整理。工具能检索时核对来源；没有实际检索时只提供线索，不把建议说成已查证资料。

资料暂时不齐，可以先试布局或流程，用明确的占位标记说明缺什么。不能编作品、编作业图片、编数据来填空。提示词有效不等于输入资料真实。

不要把“先搭知识库”设成入场条件；一次任务真正用到的材料就是起点。

## 3. 做判断：怎样算能用，谁来确认？

AI协助形成最少的验收点，判断责任对应到人：

- 本人经历、身份与想表达的意思，由本人确认；
- 内容事实和规则，由可靠来源或负责的人核对；
- 教学判断，由老师审核；
- 实际使用效果，由使用者反馈；
- 涉及物理安全或专业风险，由相应专业人员核验。

把“看起来漂亮”和“内容准确、真正有用”分开。列出当前用途必要的少量检查点即可，不写一份新手接不住的全面审计清单。

用户说“我不专业所以不敢”时，可以具体说明哪些AI能辅助、哪些能查证、哪些要人确认；不以“AI什么都会”作为底气。

## 4. 跑流程：先做一版，再看、再改

根据已有材料生成第一版，或带用户完成一个可实际执行的动作。执行工具有确认环节时等待确认，不为了提速跳过。

随后打开、试用或请相关的人看。不要仅问“满意吗”，帮助把反馈落到具体位置：“哪里不清楚、缺什么、哪些地方用不了？”一次修正最影响用途的差距，再检查。

在每轮保留已做对的部分。一次负反馈只说明这次尝试的某个问题，不能推断成员能力或整个方向不行。

化我的周报经历可作为方法例子：第一次先让Codex生成视觉样版；看到样版后有了“原来我也可以”的感受；再根据老师反馈加入真实作业截图、学生反思，继续讨论并由老师判断。这个例子说明尝试与反馈的路径，不能直接证明教学效果改善或成员同样会成功。

## 5. 留经验：我怎样做成，下次复用什么？

首次成果确认后，先问：“要不要把这次的资料、已确认成果和有效步骤，保存成一个小知识库，下次可以接着用？”已经明确要求保存则不重复问；不愿保存就正常收尾。

同意后读取 [首次成果接知识库](knowledge-base-handoff.md)，把四类内容接起来：**原始材料 → 已确认成果 → 有效方法 → 待解决问题与下一步**。沿用本轮已经确认的信息，不重新采访。已有知识库就补充；没有就从这件事建一个轻量起点，再逐步接基础包，不要求马上做完完整架构。

一条实践记录可以这样写：

> 这次想做什么；原来卡在哪；AI帮了什么；我做了或确认了什么；现在有哪些成果与证据；哪个步骤可复用；还有什么没解决。

真正保存后，重新读取文件，核对成果位置、当前版本与状态、可复用步骤和下一步。尚未验收的成果可以按草稿或待确认保存，但不能写成已验收；无法读写文件时给出待保存内容，不声称知识库已建立。

如果还在探索，只记录本轮假设、实际观察、发现的必要条件和下次验证点；不要因为一次结果就把做法升级为正式 SOP。

群内分享可选。分享前由本人决定内容，去除他人身份、联系方式和未获授权的截图；不公开需要保密的心理顾虑或公司资料。

## 个人网站练习的五步映射

| 步骤 | 做什么 | 可检查结果 |
| --- | --- | --- |
| 定交付 | 个人介绍站，用于让别人了解自己 | 本地可看的小网站，范围清楚 |
| 备材料 | 姓名或网名、介绍、真实经历、可选作品与联系方式 | 资料不编造，缺失处明示 |
| 做判断 | 本人核对信息，选择模板及想展示的内容 | 确认后再生成文件 |
| 跑流程 | 按 `huawo-website-skill` 生成、打开、检查并修改 | 完整HTML；实际做过的内容与视觉检查有记录 |
| 留经验 | 保存最终版本、有效提问和一次修改的理由 | 以后知道如何补资料、提修改要求 |

网站练习仅使用实际安装的技能及其资源。存在文件或通过脚本检查，不等于用户已成功打开、手机视觉正常或网站已上线。
